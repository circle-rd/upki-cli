# add

Enroll a new X.509 certificate for a given Common Name and certificate profile. The command generates an EC P-256 private key locally, submits an ACME order to the RA, and writes the signed certificate to `~/.upki/`.

## Synopsis

```bash
./client.py --url <RA_URL> add [options]
```

## Options

| Flag | Short | Default | Description |
|---|---|---|---|
| `--name` | `-n` | *(interactive)* | Common Name for the certificate. If omitted, you are prompted. |
| `--profile` | `-p` | *(interactive)* | Certificate profile configured on the RA. If omitted, you are prompted. |
| `--p12` | | `false` | Generate a PKCS#12 (`.p12`) bundle in addition to PEM files. |
| `--passwd` | | `None` | Protect the generated P12 file with a password. Has no effect without `--p12`. |
| `--firefox` | `-f` | `false` | Import the CA and certificate into Firefox (implies `--p12`). |
| `--chrome` | `-c` | `false` | Import the CA and certificate into Chrome / Keychain (implies `--p12`). |

## Examples

### Basic enrollment

```bash
./client.py --url https://certificates.example.com add \
    --name myserver.example.com \
    --profile server
```

### Generate a P12 bundle with a password

```bash
./client.py --url https://certificates.example.com add \
    --name myserver.example.com \
    --profile server \
    --p12 \
    --passwd "s3cr3t"
```

### Enroll and install in Firefox

```bash
./client.py --url https://certificates.example.com add \
    --name mydevice.example.com \
    --profile user \
    --firefox
```

### Enroll and install in both browsers

```bash
./client.py --url https://certificates.example.com add \
    --name mydevice.example.com \
    --profile user \
    --firefox \
    --chrome
```

## Output files

The command writes the following files to the data directory (default `~/.upki/`). All paths follow the pattern `{profile}.{name}.{ext}`:

| File | Mode | Content |
|---|---|---|
| `{profile}.{name}.key` | `0400` | EC P-256 private key (PEM) |
| `{profile}.{name}.crt` | `0444` | Signed certificate (PEM) |
| `{profile}.{name}.pem` | `0400` | Certificate + private key concatenated (PEM) |
| `{profile}.{name}.p12` | `0444` | PKCS#12 bundle — only when `--p12` is used |

## Behaviour notes

- If a node with the same name and profile already exists in the local registry, the command logs an error and exits without overwriting any files.
- A PKCS#12 file is always generated when `--firefox` or `--chrome` is passed, even without `--p12`.
- The RA URL is normalised: leading `http://` triggers a confirmation prompt; a bare hostname is treated as `https://`.
- The CA certificate is downloaded on every `Bot` initialisation and its SHA-256 hash is compared to any existing local copy. A hash mismatch triggers a confirmation prompt before the file is overwritten.
