# crl

Download the current Certificate Revocation List (CRL) from the RA and write it to `~/.upki/crl.pem`. This is useful on hosts that act as TLS servers and need an up-to-date revocation list for client certificate verification.

## Synopsis

```bash
./client.py --url <RA_URL> crl
```

## Options

The `crl` command takes no command-specific options. All global flags apply.

## Example

```bash
./client.py --url https://certificates.example.com crl
```

The CRL is written to `~/.upki/crl.pem`.

## CRL refresh for Nginx

The `upki-cli-crl.service` and `upki-cli-crl.timer` files in the repository provide a ready-made example for refreshing the CRL on a server running Nginx. After the download succeeds, Nginx is restarted so it picks up the new list.

Copy the service file to `/etc/systemd/system/`:

```bash
sudo cp upki-cli-crl.service /etc/systemd/system/upki-cli-crl.service
sudo cp upki-cli-crl.timer   /etc/systemd/system/upki-cli-crl.timer
```

Edit the service file and replace the `User`, `Group`, `WorkingDirectory`, and `--url` values:

```ini
[Service]
Type=simple
User=youruser
Group=yourgroup
WorkingDirectory=/opt/upki-cli
ExecStart=/usr/bin/python3 ./client.py --url https://certificates.example.com crl
ExecStartPost=/usr/sbin/service nginx restart
```

Enable and start the timer:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now upki-cli-crl.timer
```

The timer fires once per day at 02:00 AM with a randomised delay of up to one hour. See the [CRL renewal guide](/docs/guides/crl-renewal) for the full walkthrough.
