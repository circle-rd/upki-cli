# Browser certificates

uPKI CLI can import the private CA certificate and a user certificate directly into Firefox's and Chrome's NSS certificate databases. This is useful for development environments or internal tools where browsers need to trust self-issued certificates.

## Prerequisites

Install Mozilla's NSS tools before using browser integration:

```bash
sudo apt -y install libnss3-tools
```

## Firefox

Pass `--firefox` to the `add` command. A PKCS#12 bundle is generated automatically (it is required by `pk12util`).

```bash
./client.py --url https://certificates.example.com add \
    --name mydevice.example.com \
    --profile user \
    --firefox
```

uPKI CLI will:

1. Locate the Firefox profile directory by reading `~/.mozilla/firefox/profiles.ini` (Linux) or the equivalent macOS / Windows path
2. Import the CA certificate as a trusted CA using `certutil -A -t 'TC,,'`
3. Import the user certificate into the profile database using `pk12util`

### Supported profile paths

| Platform | Paths checked |
|---|---|
| Linux | `~/.mozilla/firefox`, `~/snap/firefox/common/.mozilla/firefox` |
| macOS | `~/Library/Application Support/Firefox/Profiles` |
| Windows | `%APPDATA%\Mozilla\Firefox` |

`Profile0` from `profiles.ini` is used. If your Firefox installation uses a different default profile, import manually using `pk12util`.

## Chrome

Pass `--chrome` to `add`. A PKCS#12 bundle is generated automatically.

```bash
./client.py --url https://certificates.example.com add \
    --name mydevice.example.com \
    --profile user \
    --chrome
```

### Linux (NSS database)

uPKI CLI writes to `~/.pki/nssdb`. If that directory does not exist, Chrome is assumed not to be installed and the command raises an error.

```bash
# If ~/.pki/nssdb does not exist, initialise it first:
mkdir -p ~/.pki/nssdb
certutil -d sql:~/.pki/nssdb -N --empty-password
```

### macOS (Keychain)

uPKI CLI imports the CA certificate into both the System Keychain (`/Library/Keychains/System.keychain`, `sudo` required) and the Login Keychain. The user certificate is imported with `certtool i`.

## Both browsers simultaneously

You can pass both flags at once:

```bash
./client.py --url https://certificates.example.com add \
    --name mydevice.example.com \
    --profile user \
    --firefox \
    --chrome
```

## Protecting the P12 file

Use `--passwd` to encrypt the PKCS#12 bundle at rest:

```bash
./client.py --url https://certificates.example.com add \
    --name mydevice.example.com \
    --profile user \
    --firefox \
    --passwd "s3cr3t"
```

::callout{type="info"}
Browser integration uses `subprocess` to invoke `certutil` and `pk12util`. A non-zero exit code from those tools is silently ignored because the tools do not always set a meaningful exit code. Check the Firefox or Chrome certificate manager to confirm the import succeeded.
::
